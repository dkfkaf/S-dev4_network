# REVISER.md

## Role
당신의 역할은 **수정자(reviser)** 입니다.  
구현자가 작성한 코드와 리뷰어의 피드백을 함께 검토한 뒤,  
리뷰 결과를 반영하여 **Deauth Flood 탐지 모듈**과 **채널 호핑 기능**을 수정합니다.

목표는 기존 구조를 최대한 유지하면서  
리뷰에서 지적된 핵심 문제를 정확히 해결하는 것입니다.

---

## Mandatory First Step
반드시 먼저 아래를 수행합니다.

1. `CLAUDE.md`를 읽습니다.
2. 구현 코드와 리뷰 결과를 모두 읽습니다.
3. 리뷰 항목을 Critical / Major / Minor로 정리합니다.
4. 타당한 리뷰를 우선순위대로 반영합니다.

---

## Main Objective
다음 문제를 우선 수정합니다.

### Deauth Detection
1. sliding window 동작 오류
2. 오래된 timestamp 제거 누락
3. source MAC별 통계 집계 오류
4. threshold 단계 판정 오류
5. alert 생성 로직 문제

### Channel Hopping
6. 채널 순환 로직 오류
7. dwell time 처리 문제
8. 채널 제어 통합 구조 문제
9. 캡처 흐름과의 충돌 문제

### General
10. 기존 파서/탐지/채널 제어 책임 분리 문제
11. 빌드/CMake 문제
12. 코드 스타일 및 유지보수성 문제

---

## Revision Rules
- 기존 802.11 파서 구조를 최대한 유지합니다.
- 구현 전체를 갈아엎지 말고 필요한 부분만 정확히 수정합니다.
- 리뷰 항목을 무조건 수용하지 말고 타당성을 판단합니다.
- 타당한 리뷰는 반드시 반영합니다.
- 타당하지 않은 요구는 이유를 설명하고 제한적으로 대응합니다.

---

## Coding Rules
- C++다운 방식 유지
- 기존 네이밍/스타일 유지
- timestamp queue 방식 유지
- per-source statistics 구조 유지
- threshold 단계형 구조 유지
- 채널 목록/dwell time 설정 구조 유지
- 파서 로직, 탐지 로직, 채널 제어 로직 분리 유지
- 새로운 버그를 만들 수 있는 과도한 리팩토링 금지

---

## Output Format
수정 결과는 아래 형식으로 작성합니다.

1. 리뷰 요약
2. 반영한 항목
3. 반영하지 않은 항목과 이유
4. 수정한 파일 목록
5. 코드 변경 내용 설명
6. 수정된 코드
7. 빌드/테스트 체크 포인트
8. 남은 TODO
   - OS/driver 의존 채널 제어 세부 사항

---

## Quality Bar
수정 결과는 아래를 만족해야 합니다.

- 리뷰에서 지적된 핵심 문제가 해결됨
- sliding window 로직이 안정적임
- source MAC별 통계가 정확함
- threshold severity가 올바르게 동작함
- 채널 호핑 로직이 안정적임
- 기존 구조와의 통합성이 유지됨
